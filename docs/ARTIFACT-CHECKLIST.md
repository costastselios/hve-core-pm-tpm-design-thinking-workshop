# Artifact Checklist

Use this after each step.

## Design Thinking
- [ ] M1: user/problem/outcome/boundaries/open questions are explicit.
- [ ] M2: evidence sources and confidence are explicit; no prevalence claims from two summaries.
- [ ] M3: shared signals, tensions, participant-specific findings, and open questions are separated.
- [ ] M4: multiple solution directions exist before selecting one.
- [ ] M5: concept has user promise, journey, action hierarchy, trust model, D/F/V assumptions, and open decisions.
- [ ] M6: prototype learning distinguishes your self-test from supplied prior participant evidence; redesign remains unvalidated.

## BRD minimum review
- [ ] Business objective/problem
- [ ] In-scope / out-of-scope
- [ ] Business requirements with stable IDs
- [ ] Acceptance criteria or measurable success conditions
- [ ] Decision owner / approval state
- [ ] Assumptions and exclusions
- [ ] Open dependencies/gates
- [ ] Traceability to evidence or accountable product decision

## PRD minimum review
- [ ] Product goals and users
- [ ] Scope and exclusions
- [ ] Functional requirements with stable IDs
- [ ] Relevant non-functional product requirements
- [ ] Acceptance boundaries/testability
- [ ] BRD traceability
- [ ] Open dependencies/gates
- [ ] No invented architecture

## Backlog minimum review
- [ ] Epics represent outcomes
- [ ] Features represent product capabilities
- [ ] Every Feature traces to PRD
- [ ] Deferred scope excluded
- [ ] Conditional candidates visibly gated
- [ ] No Stories, Tasks, estimates, RPI, architecture, or code
