# PRD Minimum Skeleton
This is a review skeleton, not a completed answer.
- Product problem/goals/users
- Product scope and exclusions
- Functional requirements with stable IDs (for example FR-001)
- Relevant non-functional product requirements
- Acceptance boundaries/testability
- BRD traceability
- Product assumptions
- Open gates/dependencies using `../../docs/GATE-RECORD.md`
- Explicitly deferred scope
- Approval status

**Reject/repair before approval if:** PRD invents architecture, requirements cannot be tested, BRD traceability is missing, deferred scope leaks in, or open gates are presented as resolved.
